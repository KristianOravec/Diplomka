INTERPRETATION
  Use the SIGNED means, not just the magnitudes: a signed mean
  near zero means the engines disagree only by sampling noise,
  while a consistent sign means a real systematic difference.

  REG rows (frozen curve a, b)
    total_kernel_runs is NOT part of this key. The fit uses
    curve_limit = min(runs, pool size, CURVE_LIMIT_MAX), so every
    runs >= 2000 is the SAME computation. Both precompute scripts
    therefore emit ONE row per (hw, fit_start) with
    total_kernel_runs = -1 (= any runs >= CURVE_LIMIT_MAX), so you
    should see 4 REG rows here, not 12.
    If a table still carries one row per runs value it predates
    that change: its repeated a,b are correct but redundant, and
    any VARIATION across them is a seeding artifact, not an engine
    difference.

  OPT rows (historical optimum O_hist)
    A systematic Py > C bias is EXPECTED. Python samples WITHOUT
    replacement (pandas .sample defaults to replace=False, giving
    curve_limit distinct configs); the C samples WITH replacement
    (~1690 distinct of 2000 drawn from a 5788 pool). Exploring
    more distinct configs finds a better minimum, pushing the
    cost-model optimum LATER -- hence larger O_hist in Python.
    Documented in evaluator.c (SAMPLING NOTE).
